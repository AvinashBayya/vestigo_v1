# Global News Providers and APIs — Vestigo Research Catalog

**Research snapshot:** 21 October 2026  
**Purpose:** Copy-ready catalog of global news providers, documented APIs, licensed feeds, RSS/Atom endpoints, and open datasets.

> **Scope:** There is no finite, authoritative list of every news outlet worldwide. Thousands of publishers operate in hundreds of languages, and APIs, feeds, access plans, and terms change. This is a broad starting catalog, not a guarantee that every endpoint is currently live. Verify all URLs, access conditions, and licenses before integration.

## Legend

- **Official API:** documented programmatic API; a key or plan may be required.
- **Licensed:** commercial/partner content feed; contact the provider.
- **RSS/Atom:** publisher feed; not a blanket right to republish article text, images, or video.
- **Website only:** no general public news API is listed here; check the publisher's official syndication options.
- **Research dataset:** useful for discovery/analysis, not necessarily a live publisher feed.

## 14. Suggested Vestigo integration plan

### Phase A — Low-cost discovery
1. Start with GDELT Project public APIs/datasets.
2. Add a curated registry of official RSS/Atom feeds.
3. Evaluate **one** aggregator API against your needed countries, languages, article history, and budget.
4. Add Google Fact Check Tools API for fact-check discovery.
5. Add publisher-specific official APIs only when they materially improve coverage.

### Phase B — Evidence metadata

Use a structure like this for each collected item:

```json
{
  "providerId": "bbc-world-rss",
  "providerName": "BBC News",
  "providerType": "publisher_rss",
  "sourceUrl": "https://publisher.example/article",
  "title": "Article title",
```

### Phase C — Provider registry fields
- `providerId`, name, region, languages, topics.
- `integrationType`: `official_api`, `licensed_api`, `rss`, `atom`, `dataset`, or `manual`.
- Endpoint/feed URL, auth method, environment variable name for credentials.
- Rate limit, timeout, retry policy, last successful fetch.
- Terms URL, license status, retention and redistribution rules.
- Enabled flag, verification timestamp, health state.
- Error states distinguishing `no_results`, `provider_unavailable`, `rate_limited`, `auth_required`, and `blocked_by_terms`.

### Phase D — Quality and reliability
- Test endpoint availability, parsing, pagination, and duplicate handling.
- Normalize article URLs and publication timestamps.
- Track language/country only when sourced or reliably detected.
- Detect wire-service syndication; multiple outlets repeating one wire story are not necessarily independent corroboration.
- Track API cost, quota, and terms changes.
- Re-verify providers periodically.

## 15. Legal, licensing, and reliability cautions

1. An API or RSS feed is **not** a blanket republication license.
2. Many APIs return only title, description, URL, or short excerpt—not full article text.
3. Respect terms, authentication, paywalls, rate limits, robots policies, and anti-bot controls. Do not bypass access restrictions.
4. Preserve attribution and source URLs.
5. Store only what you are permitted to retain; implement retention and deletion policies.
6. A publisher may correct or retract an article. Preserve version/correction history where available.
7. Do not count syndicated copies as independent corroboration without checking source provenance.
8. Free tiers are for evaluation and may not permit commercial use.
9. Recheck official docs before implementation; APIs, prices, endpoints, and terms change.

## 16. Recommended MVP shortlist

| Priority | Integration | Why |
|---|---|---|
| 1 | GDELT Project | Broad global discovery and event metadata with low barrier to experimentation |
| 2 | Official RSS/Atom registry | Geographic and language diversity without paying for a large feed immediately |
| 3 | Google Fact Check Tools API | Adds direct fact-check discovery |
| 4 | One aggregator (NewsAPI, The News API, Currents, Mediastack, or World News API) | Normalized search; choose after a coverage/cost test |
| 5 | NYT and Guardian APIs | Documented publisher APIs with explicit access terms |
| 6 | AP and other licensed wires | Add only when the budget and license justify them |
| 7 | Regional publishers | Fill gaps revealed by real coverage testing |
