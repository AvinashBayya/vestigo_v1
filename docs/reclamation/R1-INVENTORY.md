# R1 inventory: every export of `legacy/src/utils/cases/`

Reference for R1, the case analysis engine (R1-0, 2026-10-08). Read-only on `legacy/`: nothing here is ported yet. Every export statement in the 15 files under `legacy/src/utils/cases/` has exactly one row, checked by script against the source (224 export lines, 224 rows). Each file was read in full; the legacy modules they delegate to were read as far as the verdicts needed (listed at the end). The capabilities these rows belong to are audited in `R1-HONESTY.md`; the sub-stages that port them are in `R1-PLAN.md`.

**Columns.** *R0 bin* is the bin from `docs/reclamation/legacy-classification.md`. R0 bins functions, classes and objects holding functions, so types, interfaces and plain constants show "—". *Lines* is the declaration's first line and, in brackets, its length. *Inputs* is what the export needs to compute anything.

**Verdicts.** PORT-AS-IS: pure, no fabrication patterns, maps cleanly to our types. PORT-ADAPTED: pure but in legacy shapes; needs mapping to our evidence, entity and claim types. REWRITE: fabrication-flagged, or the logic is sound but the output is invented; the idea is kept, the code is not (the exact line is in the REWRITE register below). DROP: UI-only, dead, or specific to the defence scope, ADITI or PS-18, as the brief defines it, and also code that exists only to manage browser storage or that server-side storage has replaced. That widening is the inventory's, not the brief's, and is raised with D-17. NEEDS-DECISION: the owner must decide (`R1-PLAN.md`, Decisions for the owner).

**Already built here.** A verdict judges the legacy code. Where its idea already exists in this repo, the row says **Already built here** and names what; nothing of it is ported, whatever its verdict (`R1-PLAN.md`, appendix).

No legacy test imports any of these modules (`legacy/tests` was searched), so R1 writes every test; there is nothing to bring across.

## Reconciliation with R0

R0 has **86** rows for `src/utils/cases/` (PURE 42, UI/DEAD 37, FABRICATION-FLAGGED 4, IO-BOUND 3). Every one of the 86 is a row here with the same bin (checked by script, by export name and bin). The other **138** rows are exports R0 does not bin: 61 interfaces, 18 types and 59 constants. 86 + 138 = 224. No row is missing and none is counted twice.

Where the reading disagrees with R0's bin (R0 states its own limits: calls inside a file are not followed, calls through a store are not followed, and a hit in a non-exported helper does not flag its caller):

- **PURE that is not.** `buildCaseIntelligenceBreakdown` calls the file-local `buildSection`, whose line 410 `? count(ctx.input.geointHypotheses ?? 0)` trips both the line pattern and `no-fabricated-fallback`. `deleteCaseCascade`, `listCases`, `runsForCase`, `attachOsintRun`, `setRunStatus`, `deleteCaseRun`, `deleteRunsForCase` and `evictedCaseIds` read or write browser storage through the legacy stores they call.
- **UI/DEAD that is live.** `serializeCaseContext`, `buildGroundedPrompt`, `assertsCertainty`, `evidenceConfidenceFor` and `analyseCaseGrounded` (which is I/O: it calls the model) are called inside `case-analysis.ts`; `isSecretKey` and `summariseValue` inside `case-context.ts` (`isSecretKey` at line 243; `summariseValue` from `buildCaseContext` at lines 320 and 398); `observedAtByCollector`, `toContradictionInputs` and `isTraceable` inside `case-contradictions.ts`; `evidenceByCollector`, `entitiesByCollectorId` and `relationshipsByCollectorId` inside `case-intelligence-breakdown.ts`; `toCaseStatus` and `caseNumberOf` inside `case-runs.ts` (lines 111, 115); `isGeointEvidence` inside `case-geoint.ts`.
- **Gate hits in comments.** `case-claims.ts:66`, `case-intelligence-breakdown.ts:170` and `case-scope.ts:382` quote the very patterns they warn about. A port that copies those comments fails the gate.
- **Invented output the gate does not catch** (no pattern fires): see the REWRITE register. Examples: the merge score `0.5 + 0.15 * (n - 1)`, a correlation that counts disciplines rather than collectors, and `investigationId: ... ?? ""` (an empty string for an unknown value: CLAUDE.md §1 forbids it, and neither gate rule flags it).
